# Isolated Flutter and Rust Android builds

- Read the project's permitted write scope and preserve existing Java/C++ build evidence before changing tools. Keep SDKs, Rustup/Cargo homes, pub cache, Gradle cache and target output under the project. Set environment variables only inside build processes.
- Fetch the current official Flutter Windows release manifest from `https://storage.googleapis.com/flutter_infra_release/releases/releases_windows.json`; the former URL with `/flutter/releases/` may return 404. Lock the release hash/version and verify the archive SHA-256 before extracting.
- Inspect the actual SDK's `packages/flutter_tools/lib/src/android/gradle_utils.dart` for its Gradle/AGP/Kotlin template constants and minimum Android platform. Do not reuse an old project's wrapper blindly or bypass dependency validation. Verify Gradle archive and wrapper JAR hashes against services.gradle.org.
- If system MSYS2 Rust lacks Android standard libraries, install project-local rustup with `--no-modify-path`, an isolated RUSTUP_HOME/CARGO_HOME, and a pinned Windows GNU host toolchain plus `aarch64-linux-android` and `x86_64-linux-android`. Use NDK clang with explicit Android target/API and link `-Wl,-z,max-page-size=16384` and `-Wl,-z,common-page-size=16384`.
- Treat sdkmanager exit zero as insufficient: newer wrappers can split semicolon package names or report packages missing while exiting zero. Fall back to official repository XML archives and validate published checksums; require actual `source.properties`, `android.jar`, and build-tool files after installation.
- Validate the Android doctor category from its own platform/Java/license evidence. Missing Chrome concerns web tooling. Avoid matching only the Unicode checkmark: Windows PowerShell console decoding can corrupt the closing bracket. Keep false positive and false negative logs.
- Run native build commands through a subprocess helper that writes UTF-8 logs and captures the real child exit code. Avoid PS5 native stderr in `$ErrorActionPreference=Stop` pipelines. In PowerShell helper functions, route printed child output to Out-Host so a returned exit code does not become an array containing stdout. For .bat subprocesses, build a single cmd.exe `/d /s /c` command line with correct executable/argument quoting; verify with real flutter --version and an intentional nonzero child before relying on it.
- Place the final PowerShell `exit` after try/catch/finally, write result.json in finally, and check both step JSON exit and actual output files. Require APK signature, zipalign `-c -P 16 -v 4`, Flutter assets, both ABI Flutter/Rust libraries and ELF LOAD alignment. Compare packaged Rust code to staged artifacts after consistent stripping.
- Serialize Gradle package builds on the same Android project. Inspect owner process and its command when a build lock times out; wait for legitimate owners rather than deleting live locks or killing unrelated Java processes.
- Treat optional native features as package capabilities: preserve Cargo feature/build-script records and linked decoder symbols before stripping, then require byte identity after the exact strip transform. An always-exported `load_raw` entry point may still be an unsupported stub. Stage ABI-matching `libc++_shared.so` when dynamically linked, verify its ELF alignment and DT_NEEDED dependency closure, and keep host RAW execution separate from Android package capability.
- Keep analyze/test/build records separate. A package-only APK does not establish passing tests; skipped real FFI tests do not establish native integration. Compile a real host DLL and set the test's expected library environment variable where available. Do not install on physical devices without authorization.
- Regression-test the package checker against real APK mutations: accept the intended artifact and reject a missing ABI runtime, altered native bytes, missing required notice, malformed payload manifest and a feature-free older package. Check expected nonzero exits and diagnostic reasons; checking only a known-good APK cannot prove the verifier detects omissions.
- Keep payload manifests separate from step metadata filenames and validate their schema before iterating entries; a logger can overwrite a same-named manifest with an exit-code record. Preserve the failed attempt and repeat the complete package verification after correcting it.
- AAPT can decompress .gz assets and remove the suffix. Inspect actual ZIP entry bytes against the original and its decompressed form; prefer explicit decompression before staging and record both upstream and packaged hashes. Ship dependency notices and covered source with verified asset hashes when required.
- Fingerprint native core manifests/build scripts/source/shim, Dart, Android app/root Gradle and wrapper configuration, reused native archives and evidence tools before packaging and compare afterward. Keep unstripped decoder proof artifacts in the run directory so later Cargo builds cannot overwrite acceptance evidence.

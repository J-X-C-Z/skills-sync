# 多代理协作参考

这份文件只服务于复杂任务，不是每个请求都要执行的固定流程。

## 适用时机

当任务跨模块、需要并行调查、涉及公共接口或安全风险，或者用户明确要求子代理时，可以拆成独立闭环：定位问题 → 分析 → 修改 → 验证 → 汇报。

普通文件操作、单文件修改、简单问答和一次性诊断通常由当前代理直接完成。

## 子任务包

每个子任务应说明：

- 目标和背景
- 允许检查与允许修改的范围
- 明确禁止的操作
- 验收标准
- 失败或高风险时的升级条件
- 返回时需要提供的文件、命令和证据

## 验收

委派者不能只依据“完成”判断结果。应检查：目标是否满足、范围是否越界、修改是否最小、关键路径是否验证、是否存在安全/兼容性/数据风险，以及哪些内容仍未验证。

## 升级

遇到需求歧义、架构或数据模型选择、公共 API 变化、权限/安全问题、不可逆操作，或连续两轮修复仍失败时，暂停猜测性修改，列出事实、尝试、失败证据、可选方案和建议决策。
